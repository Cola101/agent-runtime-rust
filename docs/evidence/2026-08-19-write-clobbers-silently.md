# `workspace.write_text` 静默覆写（2026-08-19）

**没有修。** 修它要动工具契约,而那是一个该由你定的决定,不是一处补丁。
这份记的是它确实存在、以及修它的形状。

## 它是什么

`write_text`（`apps/trusted-workspace-tool/src/main.rs`）检查两件事：

```rust
let candidate = resolve_within_workspace(requested)?;   // 包含关系
if metadata.file_type().is_file() == false { … }        // 不能盖目录或设备节点
fs::write(&candidate, text.as_bytes())                  // 然后无条件写
```

**它不检查文件当前的内容。** 所以：

1. agent 某个时刻读了文件，产出新内容
2. 人在审批卡上看到对比，批准
3. 这中间文件若被改过——编辑器、另一个 Run、另一个工具——写入**静默盖掉**

差距清单第 21 行「Workspace 冲突处理」早就写着「**不得静默覆盖**」。它现在就是。

## 这一轮的写审批让它更要紧，而不是更安全

审批卡现在画出这次写入会改掉什么。那让人**更愿意**批准，因为看起来有依据了——
而那份依据是客户端**另读一次文件**算出来的，和 Runtime 真正会写的那一刻之间
隔着一整段时间。批准的是一个可能已经过期的对比。

**这不是客户端能修的。** 客户端只是把 `text` 转述给 Runtime；决定写什么的是模型。

## 修它的形状（三选一，代价不同）

1. **写入带上预期的前置状态**（内容摘要），不匹配就拒绝。
   契约变化：`write_text` 多一个参数。**难点是这个参数由模型产生**——模型得先读、
   记住摘要、再写。也就是说这实际上是下面第 3 条的一部分。
2. **Runtime 侧记住这个 Run 读过什么**，写入时比对它自己的记录，不匹配就拒绝。
   模型不用改，但 Runtime 要为每个 Run 维护"读过的文件及其摘要"。
   对"agent 读了又写"这条主路成立，对"没读就写"无能为力（那种情况也许本来就该拒绝）。
3. **改成 patch/apply**（Codex 的形状）。顺带解决另一件事：现在编辑一个两千行的文件，
   模型要把两千行重新写一遍——在这一轮设的 400k token 预算下付得起，但是浪费。

我倾向 2 或 3：它们不要求模型多做对的事，而 1 要求模型自觉。
但这是契约决定，**没有动手**。

## 已经量到的

- `write_text` 的实现读过，三处检查如上，没有第四处。
- 审批卡的对比确实是客户端另读一次文件算的（`WriteReview` 用 `readFile`）。
- 差距清单第 21 行的措辞不是我加的，它一开始就写着不得静默覆盖。
